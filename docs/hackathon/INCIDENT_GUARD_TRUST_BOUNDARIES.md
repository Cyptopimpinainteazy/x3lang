# Incident failure modes vs X3 Force Field: judge evidence and limits

**Judge thesis:** AI-generated payment requests, even when prompt-injected, are not spending authorization. Owners define typed `.x3` mandates; the off-chain compiler checks proposed programs; NEAR `x3-guard` checks signed 1Click quote terms against stored mandate constraints before authorizing a deposit address. This is a **bounded policy-control layer**, not universal protection against theft, false oracles, compromised owner keys, flawed bridges, or unrestricted custody.

**Read first:** [invoice_06 mainnet proof](../../PROOF_CARD.md) (restricted agent quote acceptance after 21 mandate/quote checks, then *owner-funded* 25 USDC Solana deposit and 24.9952 USDC NEAR payout). The on-chain Guard did not custody the funds, and the agent did not sign the Solana deposit. See [seven limits](../../PROOF_CARD.md#seven-limits).

## Incident → failure mode → control → observable evidence → boundary

| --- | --- | --- | --- |
| **NEAR Intents / HOT Omni, 2026:** deposit/refund interaction generated erroneous internal credit, enabling approximately $3.86M in BSC treasury payouts. **Bridge accounting boundary**, not necessarily an unauthorized signed 1Click quote. | Pre-deposit **quote-term policy**: Guard verifies the 1Click Ed25519 signature and binds recipient, assets, minimum output, expiry/refund and mandate restrictions to **signed bytes**. This could reject a nonconforming *Guard-mediated* quote. | [Guard source](../../x3-lang/near/x3-guard/src/mandate.rs); [mainnet acceptance](../../PROOF_CARD.md); [historical Guard refusal](GUARD_TESTNET_EVIDENCE.md). | **Not a prevention claim for the HOT Omni exploit.** A valid-looking quote check does not fix a bridge's refund bookkeeping, double-credit, trusted operator, or custody vulnerabilities. X3 does not monitor all NEAR Intents flows. |
| **Bybit / Safe, Feb 2025:** compromised signing-interface JavaScript misrepresented actual transaction data and led signers to authorize a malicious transaction. **Signer/display boundary**. | The typed program plus independent mandate checks reduce the set of payments an agent can propose; the Guard reads **signed quote bytes** rather than trusting a UI label. `mandate_recipient`, `mandate_approvals` and other checks apply to Guard-mediated intents. | [Unsafe compiler edits](../../README.md#3-unsafe-payments-do-not-compile); [quote checks](../../PROOF_CARD.md); [owner approval transaction](https://nearblocks.io/txns/GFdQLrzT5tnPPdZwKLtmwpNvSwrxVHDvVg2C3WX5fsK6). | **Not protection against a compromised multisig signer, Safe proxy/delegatecall, owner FullAccess key, or unrestricted funding wallet.** A signer can authorize non-Guard actions. No Bybit exploit reproduction is claimed. |
| **KelpDAO / LayerZero, Apr 2026:** a single configured DVN (1-of-1), manipulated RPC inputs and availability failure contributed to fraudulent cross-chain messages. **Bridge attestation/finality boundary**. | X3 checks that *policy-authorized* quote terms satisfy a mandate, and its evidence workflow documents why source and destination receipts must be inspected independently. | [Claim/proof matrix](../../JUDGES.md#what-is-distinctive--claim-proof-and-boundary); [invoice_06 verifier](../../scripts/hackathon/invoice06_chain.py). | **Not a defense against compromised DVNs, untrusted finality, false message attestations or bridge quorum downgrade.** Guard does not establish cryptographic cross-chain atomicity; hardening requires separately verified multi-party attestations/finality. |
| **Synthetix sKRW oracle, Jun 2019:** an erroneous KRW rate led an automated bot to execute highly profitable conversions. **Price integrity boundary**. | `.x3` mandate can require explicit slippage bounds, minimum output, per-payment/rolling 24-hour limits and one-use nonces for **Guard-mediated** actions, restricting the *amount and frequency* of authorized payments. | [Example mandate](../../x3-lang/examples/near_mandate_agent.x3); [invoice_06 payment limits](VIDEO_WALKTHROUGH.md#the-limits-behind-this-payment); [guard tests and source](../../x3-lang/near/x3-guard/src/mandate.rs). | **Slippage and a min-output floor do not validate oracle truth or stop every arbitrage loop**; an attacker may act outside Guard or within the allowed budget. X3 does not fix Synthetix's price feeds. |
| **Grok/Bankr AI-wallet incident, May 2026 (as described in the project case study):** a permission-looking object and encoded instructions caused a compliant agent to request unauthorized transfers. **Model-to-authorization boundary**. | Owner-only mandate state is independent of model output. `mandate_per_payment`, `mandate_daily`, `mandate_recipient` and the compiler/nonce checks reject out-of-policy proposals. The mainnet agent's NEAR FunctionCall key was restricted to three Guard methods. | [Reproduce 3/3 local replay](../../scripts/hackathon/replay_grok_wallet_drain.py); [8/8 distinct red-team cases](../../scripts/hackathon/compromised_agent_redteam.py); [mainnet key evidence](../../PROOF_CARD.md#accounts-keys-and-code). | **The replay is scripted and local, not the original attack or a live mainnet refusal.** Compromised unrestricted private keys, a malicious custodian, owner keys and off-Guard spending are outside this demonstrated boundary. |
| **Solana web3.js npm compromise, Dec 2024:** malicious releases exfiltrated signing keys in runtimes that held them. **Dependency/secret boundary**. | On NEAR, the **demonstrated restricted FunctionCall key** limits calls to `agent_register_intent`, `agent_accept_quote`, `agent_record_outcome`; this reduces that *particular key's* authority under compromise. | [Mainnet restricted-key proof](../../PROOF_CARD.md#accounts-keys-and-code); [Guard mandate enforcement](../../README.md#trust-boundaries). | **Not a supply-chain fix or private-key exfiltration detector.** If a poisoned dependency obtains a Solana funding-wallet key or NEAR owner FullAccess key, Guard cannot stop their direct transfers. Key isolation, lockfile integrity and hardware signing remain essential. |
| **Mt. Gox-inspired accounting failures (historical analogy):** transaction-ID changes could trigger duplicate processing, or accounting liabilities could exceed reserves. **Withdrawal ledger/custody boundary**. | A **standalone local synthetic model** links multiple txids to a stable withdrawal intent and freezes withdrawals on reserve shortfall; it allows one legitimate withdrawal. | `python3 scripts/hackathon/replay_mtgox_accounting.py --json`; `python3 -m unittest discover -s scripts/hackathon -p 'test_replay_mtgox_accounting.py'`; [limitations](MTGOX_INSPIRED_ACCOUNTING_REPLAY.md). | **Not part of deployed Guard, .x3 compiler, or Bitcoin consensus verification; not a reconstruction of the Mt. Gox theft**. The model trusts supplied txid-to-intent associations; it cannot prove real reserves. |

## Recommended 90-second judge sequence

1. **Start with an attack and a successful control:** `python3 scripts/hackathon/replay_grok_wallet_drain.py` — three local malicious programs refused for their own reasons, legitimate payment allowed. Do not count these as three mainnet denials.
2. **Prove it is more than a simulation:** open [invoice_06 proof card](../../PROOF_CARD.md), see restricted-key authorization, original source hashes, 25 USDC deposit and 24.9952 USDC payout. Label **owner-assisted** and distinguish Guard acceptance from funding/delivery.
3. **Show the trust boundary:** a model or restricted agent key cannot rewrite Guard's owner mandate; **an owner FullAccess key or unrestricted funding EOA can bypass it**. The Guard does not custody USDC or cryptographically prove cross-chain atomic settlement.
4. **Optional additional local case:** run [Mt. Gox-inspired accounting replay](MTGOX_INSPIRED_ACCOUNTING_REPLAY.md) only after stating it is a separate reference model, not a Guard feature.

## Source notes / independent incident context

- NEAR Intents / HOT Omni: [CertiK incident technical analysis, Oct 8 2026](https://www.certik.com/blog/hot-bridge-near-intents); [CoinDesk Oct 1 article updated Oct 2](https://www.coindesk.com/tech/2026/10/01/near-intents-hit-by-usd3-8-million-exploit-as-crypto-s-rough-year-of-hacks-continues). **Reported funds were subsequently returned**, so a $3.86M theft is not the same as an outstanding loss.
- Bybit: [Sygnia forensic report (Feb 25 2025)](https://smartcontractsecurity.eu/Bybit%20Interim%20Investigation%20Report.pdf); [Bybit Feb 26 update](https://www.bybit.com/en/press/post/bybit-confirms-security-integrity-amid-safe-wallet-incident-no-compromise-in-infrastructure-blt9986889e919da8d2).
- KelpDAO: [LayerZero incident report (Apr 2026)](https://layerzero.network/publications/kelpdao-incident-report.pdf): the owner configured a sole DVN; an RPC compromise was involved. **Do not label this merely an admin-key exploit.**
- Synthetix: [official June 2019 response](https://blog.synthetix.io/response-to-oracle-incident/): faulty sKRW pricing; reported high nominal profits were subsequently reversed by agreement.
- Solana web3.js: [official security advisory GHSA-jcxm-7wvp-g6p5](https://github.com/solana-foundation/solana-web3.js/security/advisories/GHSA-jcxm-7wvp-g6p5), malicious versions 1.95.6 and 1.95.7.
- Grok/Bankr: [project's incident case study and local replay](../../README.md#5b-replay-a-real-wallet-drain); its reported incident framing is not an independently reproduced exploit.
- Mt. Gox: [Decker & Wattenhofer, Bitcoin Transaction Malleability and MtGox (2014)](https://arxiv.org/abs/1403.6676). The study does not support attributing the entire exchange loss to malleability.

**No audited prevention guarantee, dollar-savings estimate, or claim that X3 would have stopped any named incident is made.** Comparisons identify potential control overlap, not counterfactual proof.
