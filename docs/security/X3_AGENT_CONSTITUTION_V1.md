# X3 Agent Constitution — admission boundary v1

Status: **pure policy checks implemented; runtime enforcement NOT implemented**.

## Provenance

The original X3 constitution is `xxxstar/crates/orchestra/src/score.rs` (Orchestra's immutable ten-commandment Score). The separate operational rules and misconduct ladder are recorded in `xxxstar/docs/swarm-governance/AGENT_LAW.md`. Preserve these as two complementary layers; do **not** silently replace or rename either historical ten-rule list. See `PRIOR_WORK.md` for historical X3Lang provenance.

The first code milestone here is deliberately narrow: `x3-lang/agent_constitution.py` checks *candidate child admission*, not full constitutional enforcement. It applies selected Agent Law requirements for delegation, permission envelopes, spawn limits, lineage, budgets, and expiration.

## Trust boundary

The caller must authenticate a real operator approval and validate it binds the exact candidate manifest (and its parent, budget and expiry). The `approval_verified` argument must be generated by that trusted approval verifier, **never by a submitted agent or an LLM**. A boolean is not an authentication mechanism by itself. Do not expose this function as an unauthenticated admission endpoint.

A successful result is **not** an admission certificate. Before execution the trusted runtime must atomically:

1. Lock the parent and identity registry in a transaction.
2. Verify parent is active and unrevoked, including all ancestors.
3. Recheck candidate manifest plus approval commitment using current balances, child counts, and policy versions.
4. Reserve the child budget against the parent's remaining budget and record the descendant count.
5. Persist an immutable unique identity and hash-bound manifest, with an auditable approval record.
6. Only then grant short-lived, scope-limited runtime capabilities.

All privileged execution adapters must check live identity status and capability scope; compiler-only checks cannot prevent a stolen key from bypassing an unguarded wallet.

## Denials and guarantees

- Child cannot add capabilities or surfaces not held by parent.
- Child cannot exceed parent remaining budget, outlive parent, or claim unrelated lineage.
- Child cannot spawn when parent is at its child limit; its declared spawn limit cannot exceed parent's.
- Missing trusted approval and duplicate IDs fail closed.
- Root admission is not handled by this child-admission function and always fails closed.

## Not yet implemented

- Atomic admission with cryptographic proof verification tied to the current parent registry state (the pure Ed25519 preflight exists, but is not yet wired into durable admission).
- Durable identity registry, atomic budget reservations and race safety.
- Full ten-commandment compiler/bytecode binding and runtime adapters.
- Persistent revocation/termination and Scrapyard lifecycle.
- Cross-VM deterministic parity, multi-agent tests, and on-chain evidence.

These are mandatory preconditions before describing this code as production agent admission. The separate Scrapyard workstream must not assume a `check_admission` success is equivalent to live enforcement.

### One complete path, on a local NEAR node

[`evidence/agent-vault-local/complete-path-sandbox-20261113.json`](../../evidence/agent-vault-local/complete-path-sandbox-20261113.json) records a run of `scripts/hackathon/vault_sandbox_smoke.sh` on commit `aa8e3ae` against an ephemeral NEAR Sandbox 2.14.0 node:

- **A permitted action executes.** The 0.1 NEAR payment reached `Paid`.
- **A forbidden action cannot bypass enforcement.** A direct transfer with the agent's key failed with `RequiresFullAccess`, and attaching a deposit failed with `DepositWithFunctionCall`; balances were unchanged. A wrong recipient, an over-cap amount and a replayed payment each got a typed `X3_VAULT_DENIED` refusal. The agent could not call the owner's recovery method (`MethodNameMismatch`).
- **Revocation stops later actions.** A fresh payment after the owner revoked was refused (`owner revoked mandate`), and the earlier payment stayed `Paid`. A fresh payment under an expired mandate was refused as well.
- **The evidence is preserved.** The harness output is committed with its SHA-256, next to the compiled contract's SHA-256.

Limits: this is a disposable local chain, not testnet or mainnet. Runner observations are not consensus proofs. The owner's FullAccess key is trusted and was outside the adversary's reach. It is not the mainnet invoice_06 path, where Guard held no funds.

`x3-lang/tests/test_vault_complete_path_evidence.py` checks the committed log against its hash and the contract's refusal reasons.

## Signed child-admission preflight (Ed25519)

`x3-lang/agent_admission_signed.py` provides `approval_payload` and `verify_signed_admission`. It serializes the exact child and parent manifests as canonical JSON, domain-separated by `X3/CHILD_ADMISSION/1`, and verifies an Ed25519 signature against a **trusted parent/operator registry public key**. It also rejects altered fields, expired signatures, and approvals whose expiry outlives the child. It does **not** sign or admit agents by itself.

The caller must bind the authenticated approval to a trusted parent identity and consume the nonce atomically with identity reservation. Rechecking against a **live parent version/state** and doing budget reservations transactionally are required before issuing any capability. Never let untrusted agents provide `trusted_public_key` themselves.

To run these focused tests in a project-specific virtual environment (the cryptography dependency is explicit):

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r x3-lang/requirements-agent-security.txt
PYTHONPATH=x3-lang python -m unittest discover -s x3-lang/tests -p 'test_agent_admission_signed.py' -v
```

No live signer, runtime registration, on-chain authorization, or replay-resistant database transaction has been established by this preflight.
